# 体育中心运动损伤应急处置报告系统

值班员接警 → 快速派人；急救员到场后逐步补充记录；管理员事后复盘。
技术栈：TypeScript · NestJS · Prisma · SQLite · React（Vite）。

## 一条命令启动

```bash
npm start
```

首次运行会自动：安装依赖 → `prisma db push` 建库 → 写入演示种子数据 → 并发启动前后端。

- 前端（值班屏）：http://localhost:5173
- 后端 API：http://localhost:3000

已安装依赖后只想重启服务：`npm run dev`。
端到端自动演示（需服务已启动）：`bash scripts/e2e-demo.sh`。

## 演示账号（登录页直接点选，免密码）

| 账号 | 角色 | 权限 |
| --- | --- | --- |
| `duty` | 前台值班员 | 登记报警、标记重复报警；普通且无人接手的求助可标记误报；**不能结案、不能关闭高风险/已接手事件** |
| `medic1` / `medic2` / `medic3` | 急救员 | 接单（抢单）、现场评估、处置、联系家属、换班交接、转院、发起升级 |
| `admin` | 管理员 | 升级处置、误报仲裁、**唯一可以结案的角色**、查看全部事件 PII |

种子数据：一起「处置中」的踝扭伤事件（含完整历史与一条已保留原文的更正）、
一起「待接手」的胸痛求助（用于抢单演示）、一起三天前「已结案」事件（复盘演示）。

## 四个核心演示

### 1. 多人抢单（唯一有效接手人）

用任意急救员身份（medic1/2/3）打开待接手事件 `INC-…-002`：

- 页面中部「🧪 多人抢单并发演示」选择两名不同急救员，点击**开始抢单**——
  前端用两个身份令牌在同一瞬间（`Promise.all`）发起接单；
- 结果一胜一负：胜者成为**唯一有效接手人**，事件转「处置中」；败者得到「对方已接手」。
- 后端用事务 + 条件更新（`updateMany WHERE currentHandlerId IS NULL`）+ SQLite 写锁重试保证，
  任意并发强度下只有一人成功，也可开三个浏览器窗口同时点「立即接单」复现。

### 2. 事件升级

- 急救员在「现场评估」表单勾选**判定为高风险** → 事件自动升级、时间线追加升级记录、
  全体管理员收到模拟 App 推送；也可用「⚠️ 升级为高风险」人工升级。
- 升级后前台值班员尝试关闭会收到 403：**高风险情况前台不能直接关闭，须管理员处置**；
  结案按钮仅管理员可见。

### 3. 查看权限（伤者 PII）

- 伤者姓名、证件、电话、既往史等资料：默认对所有人**脱敏**显示；
- 只有该事件 `Participant` 名单中的人（接手人、换班接手人）和管理员能解锁完整资料，
  非参与者调用 `?fullPii=1` 直接返回 403；
- 未参与处置的急救员可在一起自己没接手的事件上验证看到的是「🔒 已隐藏」。
- 其他权限：处置记录只能由参与者/管理员追加；更正只能改本人记录（管理员可改全部）。

### 4. 完整处置时间线

对一起事件依次操作，详情页时间线按时间追加、只增不改：

接警登记 → 接手 → 现场评估（可传现场照片，本地保存）→ 处置 → 联系家属（模拟短信回执）
→ 换班交接（处置人变更，事件号不变）→ 呼叫 120（模拟派车单）→ 转院（模拟医院接收回执）
→ 内容更正（**原文划线保留**）→ 管理员结案。

误报、重复报警、换班、转院全部沿原事件号保留：
- 重复报警：值班员「🔗 标记重复报警」填入原事件号，本单状态置为 DUPLICATE，
  原事件时间线同时追加一条合并记录；
- 误报：事件标记为 FALSE_ALARM 并写明原因，记录不删除，管理员可事后复盘；
- 换班/转院：只更新处置人与追加记录，事件号、历史记录连续。

## 模拟外部接口（本地）

| 接口 | 说明 |
| --- | --- |
| `POST /mock/notify` | 短信 / App 推送网关，返回消息回执 |
| `POST /mock/ambulance/dispatch` | 120 急救中心派车，返回派车单号/车辆/ETA（高风险派负压车、优先级更高） |
| `POST /mock/hospital/receive` | 医院急诊接收，返回回执号与分诊等级 |

业务服务通过 HTTP 自调用这些接口（见 `MockGateway`），每次请求与回执都落库，
在事件详情「🏥 急救机构回执」「🔔 通知记录」中可查。附件保存在 `server/uploads/`。

## 关键业务规则

- 报警只需地点、发生时间、伤者简要、当前处置人，提交即推送全部当班急救员，不要求先写长报告；
- 值班屏列表中 `PENDING` 事件始终置顶并有「待接手」闪烁标记；
- 事件状态：`PENDING 待接手 → ACTIVE 处置中 → RESOLVED 已结案`，
  旁路 `FALSE_ALARM 误报` / `DUPLICATE 重复报警`；已终结事件拒绝再追加记录（409）；
- 风险等级：`NORMAL / HIGH`，升级后通知管理员且前台失权；
- 更正只允许针对评估/处置/家属联系三类记录，以新的 CORRECTION 记录关联 `correctedFromId`，原文永不覆盖。
